# S19 盘前候选与盘中均价上穿提醒

这是一个可运行的 GitHub Actions 工作包：盘前从**前一交易日**的涨停池按 S19 规则生成并固化候选；盘中只扫描这份固定候选池。连续竞价时，候选股实时价格从成交均价（VWAP）下方上穿时发送提醒。

本工作包没有“距涨停价 3 个百分点”过滤条件，也不自动下单。

## 工作流程

1. 工作日北京时间 08:45 启动（GitHub Actions schedule 使用 UTC）。
2. 用 XSHG 交易日历找到前一完整交易日，从同花顺获取该日涨停池。请求失败、响应结构异常和有效空池分别处理。
3. 复用旧仓库 `select_s19` 中已存在的选股规则，保存候选快照及筛选审计。
4. 推送盘前候选清单；若最终候选为零，推送原始池数量、题材/连板/承接筛选计数。
5. 09:15 起每 5 秒轮询候选的腾讯行情。竞价阶段只记观察，不发送入场信号。
6. 09:30 后，以腾讯行情累计成交额和成交量计算 VWAP。检测到价格从 VWAP 下方上穿时推送一次；若当时已封板，标记为 `UNFILLED`。行情超过 15 秒或数据无效时不发信号。
7. 扫描至 10:57，保存候选、逐轮评估、推送去重状态和异常日志为 Actions artifact（保留 30 天）。

## 当前选股规则

`src/s19.py` 的 `select_s19` 保留旧仓库现有逻辑：

- 题材中至少 4 只被判断为封板，题材达到宽度要求；
- 按连板高度、首次涨停时间排序，选择龙头或允许的二龙头；
- 连板门槛为配置中的 `min_streak`；二龙头门槛沿用旧逻辑 `max(2, min_streak - 1)`；
- 前一日 `time_preview` 至少 4 个点，最新值不低于最高值的 95%，且不低于预览均值；
- 排序后最多保留 `top_n` 只。

盘中“承接”与盘前 `time_preview` 是不同阶段：盘前沿用上述历史数据条件；盘中提醒使用实时 VWAP 上穿。旧代码中没有低开幅度或“迅速”的具体定义，因此本版本不增加这些数值条件。

## 本地运行

需要 Python 3.11，并安装：

```powershell
python -m pip install -r requirements.txt
$env:SERVERCHAN_SENDKEY = "你的 Server 酱 SendKey"
python src/run_signal_continuous.py
```

在 GitHub 仓库的 **Settings → Secrets and variables → Actions** 添加 `SERVERCHAN_SENDKEY`。工作流也可从 Actions 页面手动运行。手动运行同样会使用当日候选生成逻辑，并按配置时间监控。

## 配置

`config.json` 控制监控时间、行情新鲜度、主题宽度、连板门槛和候选数量。所有时间为北京时间。盘中推送条件是价格上穿 VWAP；代码不使用距涨停价百分点过滤。

VWAP 根据腾讯行情快照字段计算：累计成交额（万元）换算成人民币，再除以累计成交量（手）换算的股数。行情字段缺失或累计成交量为零时，记录 `VWAP_UNAVAILABLE`，不发信号。

## 空池与审计

`state/premarket_candidates.json` 保存交易日、数据日、来源、原始池数量、筛选计数和最终候选。每轮扫描追加到 `logs/signals/YYYY-MM-DD.jsonl`，每条记录包含候选数、逐股状态、价格、VWAP、行情时间和推送结果。数据获取错误会作为错误退出，不伪装成有效空池。

通知服务接受发送不等于用户已收到，也不代表真实成交；所有提醒仅是观察信号，不会提交订单。
