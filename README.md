# S19 工作流（目标定义）

本文定义 S19 每个交易日应执行的工作流和需要保留的审计信息。它是目标规范，不代表当前 `s19-346-` 仓库的实现已经符合本文。

## 目标

盘前用**前一交易日已经完成的数据**确定当日候选；盘中只跟踪这份固定候选池，并用新鲜的实时行情判断信号是否仍可成交。候选池不得在盘中改用“当日涨停池”重算，也不得因当日结果回填或重写。

## 每日流程

1. **确定交易日和数据日**
   - 使用交易所交易日历确定当日是否开市，以及最近一个完整的前置交易日。
   - 记录交易日、候选数据所属交易日、生成时间、数据源和原始记录数。
   - 节假日或非交易日直接结束，不生成空池提示。

2. **生成并固化盘前候选池**
   - 从前一交易日收盘后可取得的历史数据生成候选；选择规则沿用已确认的 S19 规则，不临时添加条件。
   - 候选数据必须足以复现选择结果。至少保存原始股票代码、名称、题材标签、前一日连板信息、相关承接/分时数据，以及每只股票通过或淘汰的原因。
   - 生成后写入带交易日和数据日的候选快照。盘中扫描只读这个快照。
   - 若原始数据请求失败、响应结构异常或数据日期不符，应报数据错误并停止；不能把“取数失败”当成“有效空池”。
   - 若原始数据成功但筛选结果为零，应明确记录“原始记录数”和各阶段淘汰数，推送空池状态。

3. **盘中跟踪固定候选**
   - 从配置的监控开始时间开始，逐只查询候选的实时行情；记录行情源、行情时间戳、接收时间和行情年龄。
   - 仅接受有效且足够新鲜的行情。失效、过期或关键字段缺失时记录为行情数据问题，不生成信号。
   - 竞价观察与连续竞价信号分开标识。竞价信息是观察，不等于可成交信号。
   - 连续竞价时按 S19 已确认的入选规则判断候选，并按原策略的成交条件区分“可成交信号”和“封板/无法确认成交（UNFILLED）”。
   - 不擅自增加“距离涨停价 N 个百分点”等入选或推送门槛。任何规则变更必须先更新策略定义和配置，并能在日志中看出其版本。
   - 对同一股票、同一信号阶段做去重；去重状态按交易日隔离。

4. **结束和复盘**
   - 到配置的扫描结束时间后停止轮询。
   - 保存候选快照、逐轮评估、成功推送记录、异常与数据质量信息，供次日复盘。
   - 复盘以实际日志和行情时间戳为准；不得用收盘后数据推断盘中当时已知的信息，也不得把通知服务接受发送等同于用户已收到或真实成交。

## 空池必须可解释

每次候选池生成至少输出以下计数，避免只留下一个 `candidates=0`：

| 阶段 | 必须记录 |
| --- | --- |
| 数据获取 | 数据日期、来源、请求是否成功、原始记录数 |
| 解析归一化 | 可解析记录数、字段缺失/无效数 |
| 题材筛选 | 题材数、每个题材的成员数、达到宽度门槛的题材数 |
| 龙头筛选 | 龙头/二龙头候选数、连板门槛淘汰数 |
| 承接筛选 | 分时数据缺失数、承接条件通过数、淘汰原因 |
| 最终结果 | 最终候选数、候选明细、规则版本 |

“原始记录数为 0”只有在请求成功且数据日期正确时，才表示来源确实返回空数据；请求失败、解析失败和筛选后为空必须使用不同状态。

## 当前仓库实现的已知差异（2026-10-13 核对）

当时 `huvan9527-a11y/s19-346-` 的 `main` 版本中，`src/run_signal_continuous.py` 从前一交易日同花顺涨停池取数，再调用 `select_s19()`。该选择器包含题材至少 4 只封板、连板/龙头排序和 `time_preview` 承接过滤。它只打印最终候选数，没有记录足够的分阶段淘汰统计，因此单凭 `PREMARKET_POOL_READY ... candidates=0` 无法判断空池产生在哪个环节。

该版本的盘中扫描还定义了距涨停价不超过 3 个百分点的 `PRESEAL_BUFFER_POINTS` 条件。这不是本规范认可的 S19 选股规则；在策略所有者确认前，不应将其描述为原有规则或继续当作策略门槛使用。

## 验收标准

- 候选的输入数据日严格早于扫描交易日，且快照可复现。
- 空池可以区分数据源为空、数据错误和策略筛选为零。
- 盘中扫描只查询固化的盘前候选，不从当日涨停池替换候选。
- 推送能区分竞价观察、正常信号、封板未成交、过期行情和数据异常。
- 不存在未经确认的选股/推送门槛；每项策略规则均有来源、版本和日志证据。
